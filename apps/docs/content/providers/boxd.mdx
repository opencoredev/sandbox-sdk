`boxd()` runs a persistent, isolated Linux machine through [boxd](https://docs.boxd.sh). The adapter uses `@boxd-sh/sdk` 0.2.17 or later.

## Installation

```package-install
npm i @opencoredev/sandbox-sdk @boxd-sh/sdk
```

Set `BOXD_API_KEY` on your server. Keep the key out of browser bundles.

## Basic usage

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { boxd } from "@opencoredev/sandbox-sdk/boxd";

await using box = await createSandbox(boxd());
console.log((await box.run("uname -a")).stdout);
```

## Configuration

`boxd({ apiKey, baseUrl, image, requestTimeoutMs })` accepts an explicit key, API endpoint, image, and request deadline. The deadline defaults to 30 seconds; initial readiness defaults to 90 seconds when no override is given. Images must include Python 3, Git, GNU tar, and `nohup`. The SDK checks these tools and creates `/workspace` and `/var/lib/sandbox-sdk`, owned by the guest user, with the first command or file operation. With a `key` or custom labels it does this at creation instead, so discovery works right away. A non-root image must provide passwordless `sudo -n` for this one-time setup.

## Keys and labels

Key mode is **best-effort**. Keys, labels, and creation time live in `/var/lib/sandbox-sdk/metadata.json`. Names beginning with `sbxsdk-` identify candidate machines; listing reads their marker files and can wake sleeping machines. A new adapter instance can find the same machine. Keep the generated name and marker file intact, and keep secrets out of labels.

Use a [`locator`](/concepts/sandboxes-and-keys#exact-and-best-effort-keys) for exact get-or-create across concurrent requests.

## Size, network, and lifetime

This adapter accepts the service's default size and `network: "all"`. Explicit sizes, `network: "none"`, allow lists, `idleTimeoutMs`, and sandbox `timeoutMs` fail with `unsupported` before allocation.

boxd's empty egress allowlist means unrestricted access. Its host-bound secrets may admit additional destinations. The adapter therefore exposes no network-policy capability. It creates an isolated machine with auto-suspend and auto-destroy disabled; isolation removes metadata access and machine peers, but does not block internet access.

## Commands and files

Commands use the native `streamExec()` bidirectional stream. The adapter sends command, environment, cwd, and stdin as JSON over stream stdin, then closes it. It never uses boxd's `env` exec option, which the native SDK prepends to command text. Stdout and stderr stream live, with incremental UTF-8 decoding. Timeout or abort cancels the native stream, whose server kills the entire remote process group. If the stream cannot confirm exit, a guest lock and cancellation marker prevent a late launch while a follow-up call kills and checks any recorded process group. An unconfirmed cleanup still fails with `outcome_unknown`. A bad cwd returns a failed command without deleting the machine.

A successful `box.run("true")` uses one native exec, including creation and removal of the core activity record. It uploads no supervisor or per-command files. Cancellation may need a separate call to remove its activity record.

Whole-file reads and ranges use bounded byte-exact native exec calls. Writes use `machines.files.upload()` once when the parent exists. Missing parents trigger directory creation and an upload retry. Directory listings and file metadata use Python.

## Pause and snapshots

`pause()` and `resume()` use boxd's suspend-to-memory API. Snapshots, restore through `from`, and terminals are not exposed by this adapter; native APIs remain available through `box.native.client`.

`box.close()` detaches the local handle. `box.destroy()` deletes the machine. The metadata marker survives pause and reconnect.

## Previews

`box.preview(port)` pins the machine’s default HTTPS route to that port. Bind your server to `0.0.0.0`. The adapter reads the hostname from the native proxy list. Requesting another port changes the same route, including earlier preview URLs. No up-front port declarations are required.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `BOXD_API_KEY` | Required API key, overridden by `apiKey` |
| `BOXD_BASE_URL` | Optional native SDK endpoint, overridden by `baseUrl` (`baseURL` is a deprecated alias) |

## API reference

`boxd(options?)` returns a provider with the `"pause"` capability. `box.native.machine` is typed boxd machine metadata and `box.native.client` is the official `Boxd` client.

## Preview and file transfer limits

Previews use the machine’s default hostname, `<machine>.boxd.sh`, covered by the provider’s `*.boxd.sh` certificate. Nested named routes can fail TLS while their individual certificates are unavailable. TLS verification stays enabled. The adapter pins the default route to the requested port and disables its browser bot challenge so server-side HTTP clients can connect. A VM has one default route: requesting a different port changes where earlier preview URLs point. Add authentication to any app you expose.

The native SDK streams uploads above 3 MiB, so large writes need no adapter chunking. Native multi-MiB downloads can truncate their final block or exceed the request deadline. The adapter reads binary data through bounded native exec calls instead, with one call for files up to 1 MiB and additional calls for larger files. Each read chunk retries at most once on a native timeout or unavailable error; writes and arbitrary commands are not replayed. Files must remain unchanged during a multi-call read.

## Limitations

- No explicit sizes, egress restrictions, idle deadlines, hard sandbox lifetimes, snapshot restore, or terminals.
- Discovery reads guest metadata, which can wake machines and makes list operations more expensive.
- Live cloud behavior has a separate opt-in test gated by `SANDBOX_BOXD_LIVE=1` and `BOXD_API_KEY`.

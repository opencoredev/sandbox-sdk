title: Sandboxer
description: Run Ubuntu microVMs on Sandboxer in two regions. Size presets, pause and resume, named snapshots, and cookie-authenticated previews.
---

`sandboxer()` runs each sandbox as an Ubuntu 24.04 microVM on [Sandboxer](https://sandboxer.com), with Node.js 22, Python 3, and Git installed.

## Install

```package-install
npm i @opencoredev/sandbox-sdk@next @boatdev/sdk
```

Sandboxer speaks a Boat-compatible API, so the adapter uses `@boatdev/sdk`. Set `SANDBOXER_API_KEY` on your server, and keep it out of browser bundles. `SANDBOXER_REGION` is optional.

## Quickstart

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer());
const result = await box.run("python3 --version");
console.log(result.stdout);
```

`await using` deletes the VM when the block ends.

## Run commands

Await `box.run` for the result, or iterate it to stream output as it arrives.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer());
const result = await box.run("ls -la", { cwd: "/workspace", timeoutMs: 30_000 });
console.log(result.exitCode, result.stdout);

for await (const chunk of box.run("for i in 1 2 3; do echo $i; sleep 1; done")) {
  process.stdout.write(chunk.text);
}
```

## Files

Relative paths resolve against `/workspace`.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer());
await box.files.write("notes/todo.txt", "ship the docs\n");
console.log(await box.files.read("notes/todo.txt"));
console.log(await box.files.list("notes"));
```

## Background processes and previews

No ports to declare. The preview needs the `Cookie: __sbx_auth=...` header in `preview.headers` on every request. Treat it as a secret.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer());
await box.start("python3 -m http.server 3000", { name: "web", ready: { port: 3000 } });
const preview = await box.preview(3000, { waitMs: 10_000 });
const response = await fetch(preview.url, { headers: preview.headers });
console.log(response.status);
```

If your dev server checks the `Host` header, allow its preview host name under `.box.sandboxer.com`.

## Pause, resume, and snapshots

`pause()` stops the VM and waits for the stop to finish. Sandboxer normally restores memory and running processes on resume; its cold-boot fallback can lose them. `snapshot()` saves a named disk snapshot and returns its name.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer(), { key: "user:123" });
await box.pause();
await box.resume();

const { id } = await box.snapshot();
await using copy = await createSandbox(sandboxer(), { from: id });
```

Snapshots outlive their source. Delete them through `DELETE /named-snapshots/{name}`. A restore must run in the snapshot's region.

## Size, network, and lifetime

| Preset | Native type | vCPU | Memory | Disk |
| --- | --- | --- | --- | --- |
| `small` | `small` | 2 | 4096 MiB | 12 GB |
| `medium` | `default` | 4 | 8192 MiB | 50 GB |
| `large` | `large` | 8 | 16384 MiB | 125 GB |

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { sandboxer } from "@opencoredev/sandbox-sdk/sandboxer";

await using box = await createSandbox(sandboxer({ region: "eu-central" }), { size: "small" });
```

Exact sizes, `network` other than `"all"`, `idleTimeoutMs`, and `timeoutMs` fail with `unsupported`. Trial accounts allow `small` and `default` sizes and two active sandboxes.

## Configuration

| Option | Type | Default | Env var |
| --- | --- | --- | --- |
| `apiKey` | `string` | | `SANDBOXER_API_KEY` |
| `baseUrl` | `string` | `https://sandboxer.com/api/v1` | |
| `machine` | `"small" \| "default" \| "large" \| "xlarge"` | `"default"` | |
| `region` | `"us-east" \| "eu-central"` | Nearest to the caller | `SANDBOXER_REGION` |
| `requestTimeoutMs` | `number` | `90_000` | |

`us-east` is Ashburn, Virginia, and `eu-central` is Helsinki. A per-create `size` wins over `machine`. `box.native.region` and `box.native.regionSource` report where the VM landed, and `box.native.createSnapshot(name)` takes a snapshot under a name you choose.

## Limitations

- Keys are best-effort, and the encoded key and labels must fit a 120-character name.
- No custom sizes, network restrictions, idle timers, hard lifetimes, or terminals.

## How it works

- `createSandbox` makes two control-plane calls: the create and a metadata rename. Workspace setup runs inside the first command or file operation.
- Sandboxes are created with `noEnv: true`, so they get none of your account's saved secrets.
- Creates, resumes, and forks count as starts against your account's rate limits.
- `destroy()` sends Sandboxer's delete confirmation header and waits for the deletion to finish.
- Usage from `/sandboxes/{id}/usage` is machine time, not plan payments or credits.

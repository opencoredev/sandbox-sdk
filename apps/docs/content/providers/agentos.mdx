---
title: Rivet agentOS
description: Run command and file tasks locally in V8 and WebAssembly, without Docker or a cloud account.
---

`agentos()` runs a small local runtime from Rivet. For real Linux, native dependencies, SDK background processes, or preview URLs, choose [Docker on the Local page](/providers/local).

## Installation

```package-install
npm i @opencoredev/sandbox-sdk @rivet-dev/agentos-core@0.4.1
```

The optional peer loads dynamically on creation. It includes a platform-specific Rust sidecar. No account, API key, or Docker daemon is required. Rivet publishes Linux glibc and macOS sidecars for x64 and arm64; native Windows is not supported.

## Basic usage

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { agentos } from "@opencoredev/sandbox-sdk/agentos";

await using box = await createSandbox(agentos());
await box.files.write("hello.txt", "hello");
console.log((await box.run("cat hello.txt")).stdout);
```

This prints `hello`. Commands execute in agentOS's virtual process table. JavaScript runs in V8 isolates and command tools run as WebAssembly, with a shared virtual filesystem.

## Configuration

The first sandbox downloads Rivet's Git package for agentOS 0.4.1 (about 18 MB), verifies its pinned SHA-256 digest, and installs it for Git operations and file checkpoints. Rivet caches downloads by digest. File upload and download use filesystem primitives because agentOS tar does not accept the GNU flags used by other providers. For offline use, supply a trusted local `.aospkg` file:

```ts
import { agentos } from "@opencoredev/sandbox-sdk/agentos";

const provider = agentos({ gitPackagePath: "/absolute/path/git.aospkg" });
```

## Keys

Key mode is **exact within the application process**. Factories share one registry, including concurrent creation. Reconnect, list, and reap see that registry. A separate process has a separate registry; restarting your application loses the VMs and their files.

## Network

The default `network: "all"` permits egress within agentOS's own network restrictions. `"none"` denies guest egress. An allow list accepts literal hostnames, with no wildcard patterns or URLs. Listeners are VM-local. Use `box.native.network.httpRequest()` to reach a guest HTTP server; embedded agentOS has no preview URLs.

## Environment variables

No provider credentials are required. Supply sandbox variables with `createSandbox`'s `env` or `secrets` options.

## API reference

### `agentos(options?)`

- `gitPackagePath?: string`. Trusted local Git `.aospkg` file. Omit it to use Rivet's pinned package.

Returns a provider for `createSandbox`, `connectSandbox`, `listSandboxes`, and `reapSandboxes`. `box.native` is the typed `AgentOs` VM. `close()` detaches a handle and `destroy()` disposes the VM.

## Limitations

- This is a virtual OS, not a Linux kernel. It cannot run arbitrary Linux binaries or native Node addons. Node and npm use agentOS's compatibility layer.
- SDK background-process handles and preview URLs throw `unsupported`. Native process and HTTP APIs are available on `box.native`.
- Pause, snapshots, SDK terminals, machine sizes, idle deadlines, and sandbox hard lifetimes are unsupported. Command timeouts and cancellation work.
- Local Git clone, commit, status, and file checkpoints work. Local Git push stalls in agentOS 0.4.1; use Docker for workflows that need push.
- Files and identity last only as long as your application process.
- The runtime and Git package require local disk space. The published 0.4.1 Linux x64 sidecar occupies about 144 MiB on disk; the first online creation also downloads Git.

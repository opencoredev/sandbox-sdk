---
title: Memory
description: An in-process fake provider for tests. Files in a map, commands from handlers you write, fake preview URLs, and no network.
---

`memory()` is a provider that runs inside your own process. No machine starts. Files live in a map, commands are answered by handler functions you register, and preview URLs are fake. It exists for fast unit tests.

The full walkthrough is in [Testing with memory()](/guides/testing-with-memory).

## Installation

```package-install
npm i -D @opencoredev/sandbox-sdk
```

No other package is needed.

## Basic usage

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { memory } from "@opencoredev/sandbox-sdk/memory";

const provider = memory({
  handlers: {
    echo: ({ args, stdout }) => {
      stdout(`${args.join(" ")}\n`);
      return 0;
    },
  },
});

await using box = await createSandbox(provider);
await box.files.write("hello.txt", "hi");
const result = await box.run("echo hello");
console.log(result.stdout, await box.files.read("hello.txt"));
```

## Configuration

- `handlers` maps a program name to a function. The function gets the parsed arguments, `cwd`, `env`, `stdin`, a `signal`, `stdout` and `stderr` writers, and access to the fake files. It returns the exit code.
- `provider.register(name, handler)` adds a handler after creation.

## Keys

Key mode is **exact**. Keys live in the provider's in-process map, so they reset when the process exits.

## Previews

`box.preview(port)` returns a URL on the `memory.invalid` host. Assert on it, but don't fetch it.

## API reference

### `memory(options?)`

- `handlers?: Record<string, CommandHandler>`

Returns a provider with an extra `register(name, handler)` method.

## Limitations

- No real shell, git, terminals, or sockets.
- State is lost when the process exits.

Test those paths against [Local](/providers/local) instead.

A provider is where sandboxes actually run. You pick one by importing its factory from a subpath and passing it to `createSandbox`. The rest of your code stays the same when you switch.

Each provider uses that company's own SDK with your credentials. Install the SDK next to Sandbox SDK. It is loaded only when you create a sandbox with that provider, so unused providers cost nothing.

## Choose a provider

| You want | Use |
| --- | --- |
| To develop locally or run CI with no cloud account | [Local](/providers/local) |
| Fast hosted microVMs with pause and snapshots | [E2B](/providers/e2b) |
| Named sandboxes on the Vercel platform | [Vercel](/providers/vercel) |
| Long-lived workspaces with labels and token-protected previews | [Daytona](/providers/daytona) |
| Unit tests with no machines at all | [Memory](/providers/memory) |

Start with `local()` while you build. Move to a cloud provider when you deploy.

## Compare

| Provider | Factory | Install | Key mode | Credentials |
| --- | --- | --- | --- | --- |
| [Local](/providers/local) | `local()` from `/local` | Docker | exact | None |
| [E2B](/providers/e2b) | `e2b()` from `/e2b` | `e2b` | best-effort | `E2B_API_KEY` |
| [Vercel](/providers/vercel) | `vercel()` from `/vercel` | `@vercel/sandbox` | exact | `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, `VERCEL_PROJECT_ID` |
| [Daytona](/providers/daytona) | `daytona()` from `/daytona` | `@daytonaio/sdk` | best-effort | `DAYTONA_API_KEY` |
| [Memory](/providers/memory) | `memory()` from `/memory` | Nothing | exact | None |

Key mode decides how reliable [get-or-create by key](/concepts/sandboxes-and-keys#exact-and-best-effort-keys) is. With a best-effort provider, pass a `locator` if two requests for the same key can arrive at once.

## Optional features

Pause and resume, snapshots, terminals, network policies, and machine sizes depend on the provider. Each provider page lists what it supports. In code, the same set is on `box.capabilities`, and methods like `box.pause()` only exist on the type when the provider has them:

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { e2b } from "@opencoredev/sandbox-sdk/e2b";

await using box = await createSandbox(e2b());
console.log([...box.capabilities]);
```

## Write your own

Each provider is a small adapter, about 200 to 400 lines, over a fixed set of primitives: create, find, connect, list, destroy, exec, file operations, and preview URLs. Everything else, including runs, processes, `$`, git, and readiness checks, comes from the core. The contract is exported from `@opencoredev/sandbox-sdk/provider`, and `runConformance` from `/testing` checks your adapter against the same suite the built-in ones pass. See [Testing with memory()](/guides/testing-with-memory#check-a-custom-provider).

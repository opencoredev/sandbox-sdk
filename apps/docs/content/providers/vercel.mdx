---

`vercel()` runs each sandbox as a [Vercel Sandbox](https://vercel.com/docs/vercel-sandbox) microVM through the official `@vercel/sandbox` SDK.

## Install

```package-install
npm i @opencoredev/sandbox-sdk@next @vercel/sandbox
```

The adapter needs `@vercel/sandbox` 3.8 or later. Inside a Vercel deployment it authenticates with OIDC and needs no configuration. Elsewhere, set `VERCEL_TOKEN`, `VERCEL_TEAM_ID`, and `VERCEL_PROJECT_ID`, or run `vercel env pull` to get `VERCEL_OIDC_TOKEN`.

## Quickstart

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel());
const result = await box.run("node --version");
console.log(result.stdout);
```

`await using` deletes the sandbox when the block ends.

## What it supports

| Feature | Support | Notes |
| --- | --- | --- |
| Commands and streaming | Yes | Live output |
| Files | Yes | |
| Background processes | Yes | |
| Preview URLs | Yes | Public `https://`; declare up to 15 ports |
| Pause and resume | Partial | Files survive; running processes end |
| Snapshots | Yes | |
| Machine size | Partial | Presets only |
| Network policy | Yes | `"none"` or a host allow list |
| Hard lifetime (`timeoutMs`) | No | Vercel's timeout resets on resume |
| Idle timeout (`idleTimeoutMs`) | No | |
| Keys | Exact | Sandbox name is a hash of the key |
| Terminal | No | |

## Run commands

Await `box.run` for the result, or iterate it to stream output as it arrives.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel());
const result = await box.run("ls -la", { cwd: "/workspace", timeoutMs: 30_000 });
console.log(result.exitCode, result.stdout);

for await (const chunk of box.run("for i in 1 2 3; do echo $i; sleep 1; done")) {
  process.stdout.write(chunk.text);
}
```

## Files

Relative paths resolve against `/workspace`.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel());
await box.files.write("notes/todo.txt", "ship the docs\n");
console.log(await box.files.read("notes/todo.txt"));
console.log(await box.files.list("notes"));
```

## Background processes and previews

Vercel routes only to ports declared at creation, up to 15. Previewing another port fails with `invalid_argument`.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel(), { ports: [5173] });
await box.start("npx vite --port 5173 --host", { name: "vite", ready: { port: 5173 } });
const preview = await box.preview(5173);
console.log(preview.url);
```

## Pause, resume, and snapshots

`pause()` stops the session. `resume()` starts a new one from the saved file system, so files survive but running processes don't. The SDK marks them failed with exit code 137; restart them by name.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel(), { key: "user:123" });
await box.pause();
await box.resume();
await box.process("vite").restart();

const { id } = await box.snapshot();
await using copy = await createSandbox(vercel(), { from: id });
```

Any SDK call on a stopped sandbox resumes it. `snapshot()` also stops the sandbox. Vercel deletes old snapshots on its own retention schedule.

## Size, network, and lifetime

| Preset | vCPUs | Memory |
| --- | --- | --- |
| `small` | 1 | 2048 MiB |
| `medium` | 2 | 4096 MiB |
| `large` | 4 | 8192 MiB |

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { vercel } from "@opencoredev/sandbox-sdk/vercel";

await using box = await createSandbox(vercel(), {
  size: "medium",
  network: { allow: ["registry.npmjs.org"] },
});
```

Vercel gives 2048 MiB per vCPU and has no disk setting, so exact sizes fail with `unsupported`. An allow list denies everything else. `timeoutMs` and `idleTimeoutMs` fail with `unsupported`; command timeouts in `box.run` still work.

## Configuration

| Option | Type | Default | Env var |
| --- | --- | --- | --- |
| `token` | `string` | OIDC | `VERCEL_TOKEN`, else `VERCEL_OIDC_TOKEN` |
| `teamId` | `string` | | `VERCEL_TEAM_ID` |
| `projectId` | `string` | | `VERCEL_PROJECT_ID` |

A token needs both IDs, or creation fails with `auth`. `box.native` is the `@vercel/sandbox` `Sandbox` object.

## Limitations

- Preview ports must be declared at creation, 15 at most.
- No hard lifetime or idle timeout.
- At most four labels, or three with a `key`.
- Pause and resume end running processes.
- No terminals.

## How it works

- Vercel enforces unique sandbox names in a project, so concurrent calls with the same key share one sandbox.
- Your `labels` become Vercel tags. Vercel allows five; the SDK uses one, and a second for a keyed sandbox.
- Command timeouts use GNU `timeout` on a new process group, so the whole tree is killed.

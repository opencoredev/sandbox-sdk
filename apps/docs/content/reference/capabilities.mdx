Sandbox SDK never drops an option it can't enforce. If you ask a provider for something it can't do, `createSandbox` throws `SandboxError` with code `unsupported` before anything runs. This page lists what each provider accepts. For a quicker overview, see [Compare providers](/providers).

## Matrix

|  | Local | Local (agentOS) | E2B | Vercel Sandbox | Daytona | Upstash Box | Railway | Boat | Tenki | Memory |

| `pause()` / `resume()` | Yes | No | Yes | Yes, processes end | Yes, processes end | Yes, processes end | No | No | Yes, with memory | No |
| `snapshot()` and `from` | Yes | No | Yes | Yes | Yes | Yes | Yes, filesystem only | No | Yes | No |
| `terminal()` | No | No | No | No | No | No | No | No | No | No |
| `network: "none"` | Yes | Yes | Yes | Yes | Yes | Yes | No | No | Yes | Yes |
| `network: { allow }` | No | Yes, literal hosts | Yes | Yes | Yes | Yes | No | No | Yes | Yes |
| `size` presets | Yes | No | No | Yes | Yes | Yes | No | Yes | Yes | No |
| `size` with exact numbers | No | No | No | No | Yes | No | No | No | Yes | No |
| `idleTimeoutMs` | Yes, on reconnect or reap | No | No | No | Yes, whole minutes | No | Yes, destroys VM; whole minutes | No | No | Yes |

## Notes

- **Pause.** Local uses `docker pause`, so processes freeze and continue on resume. E2B and Tenki pause the VM with its memory. Tenki clears `/tmp`; the adapter keeps SDK process records in durable storage and restores their `/tmp/.sandbox-sdk` link on resume. Vercel Sandbox and Daytona stop the machine and keep the disk, so running processes end. On Vercel, the SDK marks them failed with exit code 137 on resume. Call `box.process(name).restart()` to start them again.
- **Size.** Local and Vercel Sandbox take presets only, because neither can set a disk size. E2B fixes CPU, memory, and disk in the template, so any `size` fails. Each provider page lists its preset mapping, and [Machine size and network](/guides/machine-size-and-network) compares them.
- **Network.** Local enforces `"none"` but has no per-host filter, so `{ allow }` fails there. Memory records the policy and has no network to enforce it on.
- **Timeouts.** Tenki supports a native hard lifetime but rejects idle timeouts, which its current API no longer enforces. Daytona works in minutes. `idleTimeoutMs` rounds up to the next minute and `timeoutMs` rounds down, so the hard limit is never longer than you asked. `timeoutMs` below one minute fails. Memory runs its timers in your process. Local stores both deadlines on the container and enforces them when a client reconnects or `reapSandboxes` runs, so schedule a reaper if nothing reconnects.
- **Labels.** Vercel allows five tags per sandbox. The SDK uses one, and a second for a keyed sandbox.
- **Terminal.** The `terminal()` method and the `"terminal"` capability are part of the API, but no built-in provider implements them in 1.0.
- **Upstash Box.** Uses native size presets, pause/resume, full disk snapshots, and network policy. Custom idle deadlines and hard lifetimes are unsupported. Keys and labels live in sandbox metadata; listing SDK boxes reads this metadata and may wake idle boxes.
- **Railway.** Supports filesystem snapshots. It rejects all common sizes because Railway cannot set disk size, and rejects outbound network restrictions and hard lifetimes. Its idle timeout rounds up to whole minutes and destroys the VM. Preview ports must be declared at creation. See [Railway](/providers/railway).
- **Boat.** Size presets only. No SDK pause, snapshots, terminals, network policy, idle timer, or hard lifetime. Boat's default auto-stop still applies. Keys and labels share a compressed 120-character display name; [Boat](/providers/boat) explains the limit.
- **agentOS.** Supports only the `"network-policy"` optional capability. It runs locally in V8 and WebAssembly, with in-process identity. SDK process handles and previews are unsupported; native process and HTTP APIs remain available. See [Local](/providers/local) for both runtime choices.

## Capability names

`box.capabilities` is a `ReadonlySet` of these names:

| Capability | Means |
| --- | --- |
| `"pause"` | `pause()` and `resume()` exist |
| `"snapshot"` | `snapshot()` exists and `createSandbox` accepts `from` |
| `"terminal"` | `terminal()` exists |
| `"network-policy"` | `network` accepts `"none"`, and maybe `{ allow }` |
| `"size"` | `size` accepts presets, and maybe exact numbers |

A capability means the provider supports the feature in general. The matrix has the finer limits: for example, Local declares `"network-policy"` but only accepts `"none"`.

## Checked by TypeScript

Methods for optional capabilities exist on the sandbox type only when the provider declares them. Calling `box.pause()` on Memory is a type error, not a runtime surprise.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { e2b } from "@opencoredev/sandbox-sdk/e2b";

await using box = await createSandbox(e2b(), { key: "project:42" });

await box.run("npm install");
await box.pause();
```

## Check at runtime

When the provider is chosen at runtime, read `box.capabilities`:

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { e2b } from "@opencoredev/sandbox-sdk/e2b";

await using box = await createSandbox(e2b());
console.log([...box.capabilities]);
```

This prints `[ "pause", "snapshot", "network-policy" ]`.

## What fails, and when

Each of these makes `createSandbox` throw `unsupported` before the provider is called, or right after creation when only the provider can tell:

- `size` on a provider without `"size"`, or a size it can't honor. The message names what the provider allows.
- `network` other than `"all"` on a provider without `"network-policy"`, or a policy it can't enforce. E2B reads the settings back after creation and destroys the sandbox if they don't match.
- `from` on a provider without `"snapshot"`.
- `idleTimeoutMs` or `timeoutMs` on a provider that can't enforce it.
- `keyMode: "exact"` on a best-effort provider without `locator.withLock`.

Error codes are listed in [Errors](/reference/errors).

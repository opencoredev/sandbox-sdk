---
title: Capabilities
description: Which sandbox providers support pause and resume, snapshots, network policies, sizes, timeouts and previews from TypeScript, with exact limits.
---

Sandbox SDK never drops an option it can't enforce. If you ask a provider for something it can't do, `createSandbox` throws `SandboxError` with code `unsupported` before anything runs. This page lists what each provider accepts. [Compare providers](/providers) lists each provider's factory, credentials, and what it is best for.

For example, pause and resume from TypeScript (`box.pause()` and `box.resume()` in `@opencoredev/sandbox-sdk`) work on Local (Docker), E2B, Sandboxer, Luxor, Superserve, boxd, Freestyle, Instabox, Archil, Maritime and Styne. Vercel Sandbox and Upstash Box pause partly: they keep the disk but end running processes. agentOS, Baseten, Daytona, Railway, Boat and Memory have no pause, so calling `box.pause()` on them is a type error. Baseten puts an idle sandbox on standby by itself instead. The [notes](#notes) say what each provider keeps.

## Notes

- **Pause.** Local uses `docker pause`, so processes freeze and continue on resume. E2B, Luxor, boxd, Freestyle, Instabox, Archil, and Styne pause the VM with its memory. An Archil sandbox that paused itself (its lifetime or idle timeout ran out) stays asleep until `box.resume()`: a command on it fails with `unavailable`, and the SDK never wakes one by itself. Maritime pauses the VM too, has no resume call, and wakes it on the next command; an idle Maritime sandbox pauses by itself after `idleTimeoutMs` (120 seconds by default). Luxor clears `/tmp`; the adapter keeps SDK process records in durable storage and restores their `/tmp/.sandbox-sdk` link on resume. Vercel Sandbox and Upstash Box keep the disk and end running processes, which the SDK marks failed with exit code 137 on resume. Call `box.process(name).restart()` to start them again. A Vercel sandbox created with `persistent: false`, or an Upstash Box created with `ephemeral: true`, has no `"pause"` capability. Sandboxer usually restores memory and processes too. Daytona has no pause; its idle timeout stops the sandbox instead. Baseten has no pause call: a sandbox goes on standby about 15 seconds after its last request, keeps its memory, files, and processes, and resumes on the next request.
- **Snapshots.** Microsandbox takes disk snapshots, which need the sandbox stopped: a running sandbox is stopped for the capture and started again, so its processes end. A snapshot keeps the disk, not memory, and is kept until deleted. Railway and Modal checkpoint the file system only. Modal keeps a snapshot for 30 days unless `expiresInMs` says otherwise. Sandboxer snapshots are named disk snapshots that never expire.
- **Size.** Local takes presets or `{ cpu, memoryMb }`, because Docker can't enforce a disk size. Vercel Sandbox derives memory from the vCPU count, 2048 MiB each, and has no disk setting. boxd sizes come in fixed steps of 1, 2, 4, or 8 vCPU with 4 GiB per vCPU and a 100 GB disk. Modal sets CPU and memory as both the request and the limit, so a sized sandbox gets exactly that much and can't burst, and it has no disk setting. Baseten sets CPU from memory, 2 GiB per vCPU, and takes only 1, 2, or 4 vCPUs with no disk setting. Instabox takes the sizes your plan offers (2/4, 4/8, or 8/16 vCPU/GiB on Pro), and its 20 GiB disk comes with the size, so `diskGb` fails. Archil takes 1 to 32 whole vCPUs and 256 to 65536 MiB; its root disk is fixed at about 1 TB, so `diskGb` fails. Microsandbox takes presets (small 1/1, medium 2/4, large 4/8 vCPU/GiB) or any whole vCPU count with at least 128 MiB, and `diskGb` sets the writable root disk of a fresh sandbox; a restore from a snapshot keeps the snapshot's disk, so `diskGb` with `from` fails. Maritime takes its presets (small 2/4, medium 4/8, large 8/16 vCPU/GiB) or any exact size from 1 to 16 vCPU, 1 to 64 GiB in whole GiB, and 5 to 500 GiB of disk; an exact size that is a preset with no `diskGb` gets that preset's disk (medium: 50 GiB). Styne has four sizes, 2/4, 4/8, 8/16, and 16/32 vCPU/GiB with 51, 51, 111, and 251 GiB disks: the presets map to the first three, an exact size must be one of the four, and `diskGb` must be that size's disk. E2B fixes CPU, memory, and disk in the template, so any `size` fails. Each provider page lists its preset mapping, and [Machine size and network](/guides/machine-size-and-network) compares them.
- **Network.** Local, Freestyle, and Styne enforce `"none"` but have no per-host filter, so a nonempty `{ allow }` fails there. Styne's own `allowOut` opens nothing once all traffic is denied, checked live on 2026-11-23. boxd is the reverse: it takes allow lists but can't express `"none"`, because an empty boxd list means unrestricted. Luxor, Superserve, boxd, and Modal allow lists also take `*.` wildcards, and Superserve, boxd, and Modal take IPv4 addresses and CIDRs. Memory records the policy and has no network to enforce it on. Baseten takes no policy at all, and its outbound network is IPv6-only, so hostnames work and raw IPv4 addresses don't. Instabox takes no policy either, and blocks outbound HTTPS to public DNS resolvers such as `1.1.1.1:443`. Archil's free plan denies all outbound traffic whatever the policy says, and a policy on the free plan fails with `unsupported`; paid plans enforce the policy you set. Microsandbox turns `{ allow }` into deny-by-default egress rules: a host name, `*.domain` (the domain and its subdomains), an IPv4 address or a CIDR, and each allowed name also resolves. Maritime enforces `"none"`, but its allowlist egress blocked an allowed host in a live test, so a nonempty `{ allow }` fails there.
- **Timeouts.** Railway's idle timeout destroys the VM. Sandboxer's pauses it. Daytona's stops it and keeps the disk. Daytona works in minutes: `idleTimeoutMs` rounds up to the next minute and `timeoutMs` rounds down, so the hard limit is never longer than you asked. `timeoutMs` below one minute fails. Freestyle rounds the same way in seconds. boxd and Modal round both up to whole seconds. Modal caps `timeoutMs` at 24 hours, and without it stops a sandbox after 5 minutes. Vercel Sandbox applies `timeoutMs` to each session, and each resume starts a new one. Baseten turns both into lifecycle policies that delete the sandbox. Instabox's idle timeout pauses the machine and takes 5 to 30 whole minutes (default 30); its `timeoutMs` deletes the machine and takes 1 minute to 24 hours. Archil rounds `timeoutMs` down and the idle timeout up, both to whole seconds, and pauses the sandbox when either fires; `timeoutMs` takes 60 seconds to 24 hours and can't be combined with ports or previews, because traffic to a public port resumes a paused sandbox, and the idle timeout defaults to 30 minutes. Maritime's idle timeout pauses the sandbox and takes 60 seconds to 24 hours; its `timeoutMs` is a time limit counted from the create or the last resume, 1 second to 24 hours, and one command runs for at most an hour. Styne counts `timeoutMs` in running time, up to 24 hours: its clock stops while a sandbox sleeps or is paused. Styne's `idleTimeoutMs` (up to an hour) puts the sandbox to sleep, and the next call wakes it. Microsandbox rounds both up to whole seconds; `timeoutMs` is the sandbox's maximum lifetime (1 hour by default), after which it stops. Luxor supports a hard lifetime but rejects idle timeouts, which its current API no longer enforces. Memory runs its timers in your process. Local stores both deadlines on the container and enforces them when a client reconnects or `reapSandboxes` runs, so schedule a reaper if nothing reconnects.
- **Provider timers.** Some providers reject `timeoutMs` but have a timer of their own on the factory. Boat and Sandboxer take `ttlSeconds`, an auto-stop that restarts while Boat's agent works, so it is not a hard lifetime. Upstash Box takes `ttlSeconds` with `ephemeral: true` as a leak backstop. Superserve takes `autoPauseMs` and `autoDeleteMs`. The provider pages explain each one.
- **Labels.** Vercel allows five tags per sandbox. The SDK uses one, and a second for a keyed sandbox, so you get four labels, or three with a `key`. Boat and Sandboxer store the key and labels in a compressed display name of at most 120 characters. Freestyle stores them in native VM metadata, which holds about 2.9 KB once encoded. Modal allows ten tags and 1024 bytes per sandbox; the SDK uses two, keeps a third free for the tag `destroy()` adds, and uses a fourth for a keyed sandbox, so you get seven labels, or six with a `key`. Railway, boxd, and Archil keep them in a marker file inside each VM. A paused or stopped Archil sandbox is left out of `listSandboxes()` and `reapSandboxes()`, because its marker can't be read until it runs; `connectSandbox` by ID still reaches it.
- **Key mode.** agentOS keys are exact within one application process.
- **Previews.** Local returns `http://127.0.0.1` on the Docker host, so the URL works only on that machine. boxd gives one public route per machine, and previewing a new port moves it. Baseten previews are public, and `destroy()` deletes them, because Baseten keeps a preview after its sandbox is gone. Instabox previews are public and take ports 1024 and up. Archil previews are public exposed ports, opened on the first `box.preview(port)`. Maritime previews are private: the URL carries the sandbox's `?token=`, and a `path` keeps it; `maritime({ public: true })` makes previewed ports public instead. Styne previews need the sandbox's traffic token in `preview.headers`, unless the factory sets `public: true`. Microsandbox previews are public Services (`https://<slug>.<domain>`) that the adapter creates on the first `box.preview(port)` and deletes with the sandbox. Daytona, Upstash Box, and Superserve can make previews public with a factory option, and E2B can make them private. agentOS has no preview URLs, and Memory returns fake ones.
- **Terminal.** E2B and Archil have a PTY. Each terminal is a login shell running as root, with `TERM=xterm-256color`.
- **Snapshot deletion and templates.** `deleteSnapshot()` and `buildTemplate()` are root functions that take the provider, because neither needs a running sandbox. E2B stores snapshots as templates, so deleting a snapshot deletes that template. Modal stores both as images, so `deleteSnapshot()` also deletes a template built with `buildTemplate()`.
- **Upstash Box.** Listing SDK boxes reads metadata from inside each box and may wake idle boxes.
- **Railway.** Rejects all common sizes because Railway can't set a disk size; set CPU and memory with the factory's `resources` option. Its idle timeout destroys the VM. See [Railway](/providers/railway).
- **agentOS.** Supports only the `"network-policy"` optional capability. It runs locally in V8 and WebAssembly, with in-process identity. SDK process handles and previews are unsupported; native process and HTTP APIs remain available. See [Local (agentOS)](/providers/agentos).
- **boxd.** A restored snapshot keeps the source's size, image, and env. See [boxd](/providers/boxd).

## Capability names

`box.capabilities` is a `ReadonlySet` of these names:

| Capability          | Means                                                  |
| ------------------- | ------------------------------------------------------ |
| `"pause"`           | `pause()` and `resume()` exist                         |
| `"snapshot"`        | `snapshot()` exists and `createSandbox` accepts `from` |
| `"snapshot-delete"` | `deleteSnapshot(provider, id)` works                   |
| `"templates"`       | `buildTemplate(provider, spec)` works                  |
| `"terminal"`        | `terminal()` exists                                    |
| `"network-policy"`  | `network` accepts `"none"`, and maybe `{ allow }`      |
| `"size"`            | `size` accepts presets, and maybe exact numbers        |

A capability means the provider supports the feature in general. The matrix has the finer limits: for example, Local declares `"network-policy"` but only accepts `"none"`.

## Checked by TypeScript

Methods for optional capabilities exist on the sandbox type only when the provider declares them. Calling `box.pause()` on Memory is a type error, not a runtime surprise. The same goes for the provider-level functions: `deleteSnapshot(memory(), id)` does not compile.

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { e2b } from "@opencoredev/sandbox-sdk/e2b";

await using box = await createSandbox(e2b(), { key: "project:42" });

await box.run("npm install");
await box.pause();
```

## Check at runtime

When the provider is chosen at runtime, read `box.capabilities`:

```ts
import { createSandbox } from "@opencoredev/sandbox-sdk";
import { e2b } from "@opencoredev/sandbox-sdk/e2b";

await using box = await createSandbox(e2b());
console.log([...box.capabilities]);
```

This prints `[ "pause", "snapshot", "snapshot-delete", "templates", "terminal", "network-policy" ]`.

A provider typed as plain `Provider` still compiles with `deleteSnapshot` and `buildTemplate`. They then throw `unsupported` before any request when the provider lacks the capability.

## What fails, and when

Each of these makes `createSandbox` throw `unsupported` before the provider is called, or right after creation when only the provider can tell:

- `size` on a provider without `"size"`, or a size it can't honor. The message names what the provider allows.
- `network` other than `"all"` on a provider without `"network-policy"`, or a policy it can't enforce. E2B reads the settings back after creation and destroys the sandbox if they don't match.
- `from` on a provider without `"snapshot"`.
- `idleTimeoutMs` or `timeoutMs` on a provider that can't enforce it.
- `keyMode: "exact"` on a best-effort provider without `locator.withLock`.

Error codes are listed in [Errors](/reference/errors).

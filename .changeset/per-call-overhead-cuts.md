Commands add less overhead on top of each provider's own SDK. Freestyle and Superserve keep one guest supervisor per sandbox instead of starting Python for every command. boxd, Freestyle, Superserve and Tenki supervisors start faster. E2B and Upstash no longer wrap each command in an activity script; `reapSandboxes({ idleOnly: true })` finds running commands by scanning for the `SANDBOX_SDK_RUN=1` tag instead, and still treats a sandbox it can't inspect as busy. On E2B and Upstash, `files.edit` takes one call and changes the file the way that provider's own write does: in place on E2B, by replacing it on Upstash. `files.search` takes one call wherever the guest can walk files in the provider's own listing order (E2B, Upstash, boxd, Freestyle, Superserve, Tenki, Boat, Sandboxer and local), so `maxMatches` returns the same files as before; elsewhere it lists and reads as before. Upstash creates poll for readiness every 200 ms, honor `requestTimeoutMs`, ride out transient errors while the new box boots, and report `outcome_unknown` when the create answer is lost or unreadable, or when cleanup after a failed create can't be confirmed. A create whose first read of the new box stalls or keeps failing stops at the create deadline or `requestTimeoutMs`, deletes the box and reports `timeout`, or `aborted` when the caller cancels. If the guest call behind `files.edit` fails after it may have run, the edit reports `outcome_unknown`, so read the file before retrying; failures that prove nothing ran keep their own code.
